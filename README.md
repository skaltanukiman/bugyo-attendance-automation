# 奉行クラウド 勤務実績入力自動化

Windows上で作業実績Excelを読み取り、奉行クラウドの「勤務実績申請」画面へ転記するローカルCLIです。入力値の検証、下書き保存、対象月の下書きの再オープンと保存内容の照合まで行い、成功した場合だけ使用したExcelをバックアップ先へ移動します。

**ログイン・MFA・最終「申請」は利用者が手動で行います。最終「申請」は自動実行しません。** 利用者向けの簡易手順は [はじめに_使い方.md](はじめに_使い方.md) を参照してください。

## このツールが行うこと

通常実行では次の順序で処理します。

1. Excelを選択・解析し、指定した出社日・有休日と合わせて入力予定を作成します。
2. 対象画面・年月を確認し、全対象日の既存値を調べます。競合があれば入力前に停止します。
3. 日付で行を特定して入力し、各日の値を再読取します。一致済みの行は入力を省略します。
4. 保存前に全対象日の6項目（勤務体系・事由・出勤・退出・休憩・実働）を照合し、通常勤務日数・実働・休憩の合計を検算します。
5. 下書き保存を1回行い、申請期間画面から下書き一覧を開きます。対象月の下書き→詳細→申請書入力の順に開き直し、年月と全対象日の保存値を照合します。
6. 照合成功後、選択したExcelを `input/` から `filesback/日時/元ファイル名` へ移動します。

この保存後照合は、現在の `config/selectors.json` の `saveMode: reopenDraft` による動作です。

## 自動化しないこと

- 奉行クラウドへのログイン、MFA、開始前の対象画面への移動、最終「申請」。
- 未知のExcelレイアウトや休暇種別の推測、対象年月が確認できない状態での入力。
- 許可された変更を除く既存の競合値の上書き。
- 途中失敗時の自動ロールバック、成功不明の保存クリックの再試行。

Excelの空欄・作業内容・「休暇」の記述から有休や特休を判定しません。有休は明示指定した日だけ処理します。

## 初回セットアップ

1. Windowsに **Node.js 22以降**（npm付属）と **Microsoft Edge** を用意します。バッチはNodeの存在を確認しますが、バージョンの検査は行いません。
2. このリポジトリのフォルダで依存をインストールします。標準インストール済みのEdgeを使用するため、Playwright用ブラウザの追加ダウンロードは不要です。

   ```text
   npm install
   npm run check
   npm test
   ```

3. `config/settings.json` の勤務コード・ファイル保存先・Edge設定が運用に合うことを確認します。
4. 実画面の構造が現在の `config/selectors.json` と一致することを確認します。現在の設定は `verified: true` で通常実行が可能です。別環境やDOM変更時の確認手順は [docs/selectors.md](docs/selectors.md) を参照してください。

技術構成はTypeScript・tsx、Playwright、SheetJS、Zodです。Excel読取は `package.json` に指定されたSheetJS公式配布の **0.20.3** を使用します。pnpm用の `pnpm-lock.yaml` と `pnpm-workspace.yaml` もあり、pnpmを利用する場合は `pnpm install --frozen-lockfile` でインストールできます。

## 毎月の利用

### 通常実行：run.bat

1. 編集・再計算・保存を終えた対象Excelを `input/` 直下へ配置します。原本を残す場合は、原本のコピーを配置してください。ファイル名は `YYYYMM_名称.xls` または `YYYYMM_名称.xlsx`（例：`202610_勤務実績.xlsx`）。名称は自由ですが、内部レイアウトは対応テンプレートである必要があります。
2. `run.bat` をダブルクリックします。コマンドからは `npm start` でも実行できます。対象が1件なら自動選択、複数なら一覧の番号を入力します。サブフォルダ内・Excelの一時ファイル（`~$` で始まるもの）は対象外です。
3. 出社日を `3,18,25` または `3、18、25` のように日番号で入力します。ない場合はEnter。
4. 有休日を同じ形式で入力します。後で奉行上で手動入力する場合はEnterで続行できます。
5. 対象年月・日数・時間・出社日・有休日を確認します。開始確認は `[Y/n]` で、`Y`・`yes` またはEnterで続行、`n`・`no` で中止します。中止時は画面とExcelを変更しません（ログは作成されます）。
6. 起動した専用Edgeで手動ログイン・MFAを済ませ、対象月の「勤務実績申請」入力画面を開きます。対象画面は1タブだけにし、編集中の欄は確定または取消してください。コンソールへ戻りEnterを押します。
7. 全対象日の事前確認→入力→入力後検証→下書き保存→保存済み内容の再確認→Excel移動が完了するまで待ちます。自動処理中は対象画面とExcelを編集せず、Edgeを閉じないでください。
8. 完了後もEdgeは開いたままです。画面の内容を確認し、必要な未指定有休などを追記して、**利用者自身が「申請」してください**。バッチは結果を表示してキー入力を待ちます。完了後のコンソールは閉じて構いません。

現在の設定は全日付行の年月日属性と日付表示から対象年月を確認します。年月表示がない画面でも、属性の不足・別月・別年・重複・表示との矛盾があれば停止します。年月表示を読む設定に変更した場合だけ、月のみの表示に対し通常実行で年の追加確認があります。この確認は `[y/N]` で、Enterでは停止します。保存後照合と画面読取確認では年不明を受理しません。

### 出社日・有休日の扱い

| Excelと指定 | 入力内容（現在の設定） |
| --- | --- |
| 勤務実績あり・出社未指定 | 勤務体系 `205`、在宅事由 `007`、Excelの出勤・退出・休憩 |
| 勤務実績あり・出社指定 | 勤務体系 `205`、事由は空欄、Excelの出勤・退出・休憩 |
| 勤務実績なし・有休指定 | 勤務体系 `205`、有休事由 `040`。出勤・退出・休憩欄は入力しない |
| 勤務実績なし・有休未指定 | `非対象 SKIP`。行を変更しない |

実働は奉行画面の計算結果を読み、Excel由来の期待値と照合します。有休日も6項目を照合し、時刻は空欄、休憩・実働は空欄または `0.00` を要求します。

出社指定はExcel上の勤務実績日だけ、有休指定は勤務実績のない日だけ受理します。同じ日の出社・有休の二重指定はできません。月内の日番号をカンマまたは読点で区切り、重複は除去します。不正な日・指定の競合はコンソールで再入力します。入力対象が0件なら開始できません。有休を1日も指定しなかった場合は、設定された有休コードで手動入力する案内を表示します。

## 保存後の確認だけを再開する

### verify-draft.bat

下書き保存後の確認に失敗した場合など、保存済み下書きの照合だけを行うモードです。通常実行が正常完了していれば不要です。

1. `input/` に残っている同じExcelを使い、`verify-draft.bat` をダブルクリックします。**保存時と同じ出社日・有休日**を指定し、入力予定を確認して `[Y/n]` で開始します。
2. 設定ポートの起動済み専用Edgeへの接続を試し、接続できなければ起動します。必要なログインと画面移動は手動です。下書き件数・「申請期間」・OKが表示される画面を開き、コンソールでEnterを押します。「下書き:N件」は自動で開きます。
3. 対象月全体の「勤務実績申請」で状態が「下書き」の行を一意に特定し、詳細から入力画面を開いて全対象日の保存値を照合します。一致した場合だけExcelを移動します。

**勤怠欄への入力・再保存・申請・削除は行いません。** 別月・部分期間・承認待ち・重複候補・値の不一致では停止し、Excelを保持します。`verified: false` でも構造が正しい設定なら利用できますが、`saveMode: reopenDraft` が必要です。設定ファイルの `verified` は変更せず、確認済み設定でもこのモードから入力・保存はできません。

各遷移の表示待ちには現在最大60秒を設定しています。読込中表示や一時的なタイトル重複の解消、保存ボタン・日付行・読取項目が揃うことを待ちます。完了までEdgeを開いたままにしてください。終了後もEdgeは保持します。

## 実画面の読取確認（任意）

### check-screen.bat

1. 前回の専用Edgeが残っていれば閉じ、`check-screen.bat` をダブルクリックします。Excelの配置は不要です。
2. 対象年月を西暦6桁の `YYYYMM`（1900年以降）で入力し、値を確認したい日を1日指定します。
3. 起動した専用Edgeで手動ログインし、対象月の「勤務実績申請」入力画面を開きます。入力欄の編集を確定または取消してからコンソールへ戻りEnterを押します。
4. 月の全日付・各日の6項目を読み取ります。「確認成功」と指定日の値が表示されたら、実画面と一致するか利用者が確認してください。エラーなら表示された段階とメッセージを確認します。

このモードは**画面読取専用**です。クリック・自動入力・下書き保存・申請・Excel解析・Excel移動は行いません。ログファイルも作成せず、勤務値はコンソールだけに表示します。Excelとの値照合や集計検算、入力・保存の動作確認をするモードではありません。

未確認設定でも読取可能ですが、設定の構造は検証します。`verified` を変更せず、読取成功によって通常実行を有効化することもありません。実行ロックと専用プロファイルは使用し、終了後もEdgeは開いたままです。

## Excel対応範囲

`.xls`・`.xlsx` の同じ固定テンプレート1種類に対応します。拡張子は大文字でも検出できます。対象年月はファイル名の先頭6桁（1900年以降・1〜12月）で判定し、Excel内の日付と照合します。シート名は固定せず、次の見出しに一致するシートが1枚だけあることを要求します。

| セル・列 | 対応する内容 |
| --- | --- |
| `B8:M8` | `日 / 曜 / 作業 / 開始 / 作業 / 終了 / 総 / 時間 / 休 / 憩 / 実動 / 時間` の見出し |
| 10〜40行 | 1〜31日。B列は日番号、C列はExcelシリアル日付 |
| D/E列 | 出勤（作業開始）の時・分 |
| F/G列 | 退出（作業終了）の時・分 |
| H/I列 | 総時間の時・分 |
| J/K列 | 休憩の時・分 |
| L/M列 | 実働の時・分 |
| `L42/M42` | 月合計実働の時・分。日別実働の合計と照合 |

- 対象月の全日付が必要です。月末を超える行のB〜M列はすべて空欄でなければ停止します。Excelの1904日付方式も設定に従って解釈します。
- D〜M列がすべて空欄なら非勤務日です。一部に値がある場合は全組の時・分を検証し、欠落や文字列の時分を拒否します。
- 出勤は `00:00〜23:59`、退出と日別の時間組は最大 `47:59`。退出が出勤より後で、差分＝総時間、総時間−休憩＝実働、実働＞0である必要があります。
- 日跨ぎは退出を `25:30` のように24時以上で明記する形式だけに対応し、翌日扱いを推測しません。実画面の未知の翌日時刻表示も推測変換せず停止します。
- **Excel数式をNode.js側で再計算しません。保存済みの計算結果を読みます。** 使用セルに数式エラーや保存済み結果の欠落があれば停止します。Excelで再計算してから保存してください。
- 月合計は実働を照合します。月合計の休憩欄は読みません。画面への休憩・実働の期待値は小数時間の小数点以下2桁です（例：1時間30分＝`1.50`）。

未知の配置・不正な日付・時間・合計では入力を開始しません。別テンプレートは解析処理の追加が必要です。元のセル配置調査は [docs/investigation.md](docs/investigation.md) を参照してください。

## 入力・検証の安全設計

- 入力前に**全対象日**の既存値を読み、競合をまとめて確認します。この段階で競合があれば入力・保存とも行いません。
- 正規化した6項目が期待値と一致すれば `ALREADY OK` と表示し、その日の入力を省略します。全対象日が一致していても、通常実行では検証後に下書き保存を1回行います。
- 空欄への入力、勤務体系の変更、明示した出社日に残る在宅事由から設定の出社事由への変更を許可します。時刻が空欄の場合の休憩・実働 `0.00` も未入力相当として扱います。異なる非空欄の時刻・事由・時間は、これらの例外を除いて競合です。一部だけ一致していても競合項目を強制上書きしません。
- 各行の処理直前に再読取し、事前確認時から変化があれば停止します。入力した行は直後に照合し、保存前にも年月と全対象日・集計を再確認します。未確定の手入力や複数事由など、解釈できない状態では停止します。
- 現在の保存方式では、保存後に対象月の下書きを再オープンし、全対象日の6項目を再読取します。下書き件数だけで成功とせず、既存下書きの更新で件数が変わらない場合にも対応します。
- 下書き保存クリックは1回だけです。遷移・照合に失敗しても再クリックせず、Excelを保持します。最終申請を行う操作メソッドはなく、画面操作には申請を拒否するガードがあります。

日付行番号で転記先を決めたり、候補タブ・下書きの先頭を推測で選んだりしません。別タブへ開く下書き、複数階層iframe、全日付がDOMに存在しない仮想スクロールは現在の対応範囲外です。

## 設定

`config/settings.json` の現在値は以下です。相対パスはリポジトリのルートを基準に解決します。コードは先頭ゼロを保持する数字の文字列です。

| 設定 | 現在値・意味 |
| --- | --- |
| `attendance.workPatternCode` | `"205"`。勤務日・指定有休日の勤務体系 |
| `attendance.remoteReasonCode` | `"007"`。出社未指定の勤務日の事由 |
| `attendance.officeReasonCode` | `null`。出社日は事由を空欄。運用に応じて数字の文字列を設定可能 |
| `attendance.paidLeaveReasonCode` | `"040"`。明示された有休日の事由 |
| `files.inputDirectory` | `"input"`。Excelの選択元 |
| `files.backupDirectory` | `"filesback"`。成功後のExcel移動先 |
| `files.supportedExtensions` | `[".xls", ".xlsx"]` |
| `files.backupTimestampFormat` | `"yyyyMMddHHmmss"`。移動時の日本時間（Asia/Tokyo） |
| `browser.remoteDebuggingPort` | `9222`。`127.0.0.1` へのCDP接続用（設定範囲1024〜65535） |
| `browser.userDataDirectory` | `".runtime/edge-profile"`。通常のEdgeと独立した専用プロファイル |
| `browser.executablePath` | `null`。Edgeの標準インストール先から自動検出。必要なら実行ファイルの絶対パスを指定 |
| `browser.selectorsFile` | `"config/selectors.json"`。実画面の操作・読取設定 |

日時書式は `yyyy`, `MM`, `dd`, `HH`, `mm`, `ss` と区切りの `-`, `_` に対応します。例：`yyyy-MM-dd_HH-mm-ss`。ディレクトリ名を作る書式であり、パス区切りは指定できません。

### セレクタ設定

`config/selectors.json` はDOMの特定・読取・編集確定・保存確認の設定です。現在は次の運用になっています。

| 設定 | 現在値・意味 |
| --- | --- |
| `verified` | `true`。通常実行に必須。`false` または構造不正なら入力前に停止 |
| `periodSource` | `"rowDates"`。全日付行の年月日属性と日付表示を照合 |
| `saveMode` | `"reopenDraft"`。保存後に対象月を開き直し、保存値を検証 |
| `timeoutMs` | `10000`。通常の要素操作・値照合の待機時間（ミリ秒） |
| `transitionTimeoutMs` | `60000`。下書き再表示などの遷移待機時間（ミリ秒） |
| `transitionStableMs` | `1000`。一覧・詳細の操作対象が一意・表示中・読込終了の状態で安定するまでの時間（ミリ秒） |

互換用の `message` / `countAndReturn` 保存方式も実装されていますが、保存後の値再照合は行いません。現在の安全設計を維持するため、保存方式を安易に変更しないでください。`verify-draft.bat` は `reopenDraft` 専用です。確認モードやテストは設定ファイルの `verified` を自動変更しません。

全セレクタと実DOMの確認方法は [docs/selectors.md](docs/selectors.md) を参照してください。模擬画面用の `tests/fixtures/selectors.json` を実運用へコピーしないでください。

## 再実行・エラー時

コンソールの停止段階と、入力・検証・下書き保存・Excel退避の状態を確認してください。

- **入力前の失敗：** ファイル名・Excelの再計算結果・日指定・設定・対象タブ・年月・既存値の競合を確認します。
- **入力途中の失敗：** 入力済みの行が画面に残る場合があります。自動ロールバックはありません。画面を確認してから再実行してください。一致行は入力を省略しますが、全対象日を改めて確認します。
- **保存の成功未確認：** 通信切断や遷移失敗でも下書きが保存されている可能性があります。画面を確認し、保存済みなら `verify-draft.bat` で照合を再開してください。保存クリックを自動再試行せず、確認できるまでExcelは `input/` に残します。
- **照合成功後の退避だけ失敗：** 下書きは維持され、警告と終了コード2を返します。Excelを手動でバックアップしてください。ファイルが処理中に変更されていた場合は、その内容も確認してください。
- **Edge起動・ポートの問題：** 通常実行と画面読取確認は新規起動するため、前回の専用Edgeを閉じてから実行します。ポートが使用中なら停止します。再確認モードは起動済み専用Edgeへの接続を試します。

### Excelバックアップ

移動先の既定形式は `filesback/yyyyMMddHHmmss/元ファイル名`（例：`filesback/20261004123045/202610_勤務実績.xlsx`）です。日時は対象年月ではなく、退避時の日本時間です。

**退避は `rename` による移動です。コピーではなく、成功後は `input/` に残りません。** 入力検証・保存内容の確認が成功し、選択元がinput直下でシンボリックリンクではなく、解析前のSHA-256と移動直前のファイル内容が一致することを確認します。解析中の変更も検出して停止します。

同秒の日時ディレクトリが既に存在する場合は、再利用・上書き・自動連番化をせず退避に失敗します。`rename` ができない別ドライブ間の移動なども失敗となり、コピーへの切替はありません。保存確認とファイル移動は別操作なので、退避失敗によって下書きを取り消すことはありません。

### 終了コード

| コード | 通常実行・verify-draft | check-screen |
| --- | --- | --- |
| `0` | 正常完了、または開始確認で中止 | 読取成功 |
| `1` | 解析・設定・接続・入力・検証・保存確認などのエラー | 設定・接続・画面読取などのエラー |
| `2` | 下書き確認まで成功し、Excel退避だけ失敗 | 使用しない |

各バッチは処理の終了コードを保持し、キー入力待ちの後に同じコードで終了します。Nodeやtsxが見つからない起動前エラーも `1` です。

## ログ・実行時データ

通常実行と `verify-draft.bat` は `logs/` に日時・PIDを含む `.log` を作成します。ファイル名と各記録の時刻はUTCです。バックアップディレクトリの日時（日本時間）とは異なります。

ログにはExcelのパス、対象年月・日数・時間のサマリー、日別結果、競合差異、画面識別の件数、エラー時の処理状態などを記録します。対話の質問・回答をすべて保存するものではありません。生のブラウザエラー、HTML、画面URL、Cookie、ログイン認証情報は記録しません。勤務日時やファイル名が含まれるため、共有時は必要な箇所を確認してください。`check-screen.bat` はログファイルを作成しません。

3モード共通の `.runtime/run.lock` を排他的に作成して同時実行を防止します。通常の終了処理で削除しますが、強制終了などで残った場合は、**別の処理が動いていないことを確認してから、このロックファイルだけを手動削除**してください。古いロックを自動削除する機能はありません。

専用Edgeは `127.0.0.1` の設定ポートへPlaywrightからCDP接続します。日常利用のEdgeとはプロファイルが独立しており、そのタブを転記対象にしません。終了時は接続を切断し、成功・失敗とも専用Edgeを自動終了しません。

`.runtime/edge-profile` は認証状態を含む可能性があるため、共有・コミットしないでください。パスワードを設定ファイルへ書く必要はありません。`input/`・`filesback/`・`logs/` 内のデータと `.runtime/` は `.gitignore` の対象です。保存先を変更する場合も、実データが共有・コミット対象に入らないよう管理してください。

## 開発・検証

```text
npm run check
npm test
```

`check` は `tsc --noEmit` による `src/` と `tests/` のTypeScript型検査です。`test` は `tsx --test tests/*.test.ts` でNodeのテストランナーを実行します。

自動テストは架空の明細データ、生成したxls/xlsx、模擬HTMLを使い、Excel解析・業務判定・競合・入力後検証・保存後照合・モード制限・退避条件を検証します。fixtureは実奉行DOMの完全な再現ではなく、原本や認証情報はリポジトリに含めません。

ブラウザテストはMicrosoft Edgeの標準インストールを必要とし、Playwrightで独立したヘッドレスEdgeを起動します。CDPテストは一時プロファイルと空きポートを使い、切断後もEdgeが残ることを確認してからテスト自身のEdgeを終了します。**実運用の専用プロファイル・9222ポート・ログイン済み勤怠画面には接続しません。** CDPテストのみ `EDGE_PATH` で実行ファイルを変更でき、`--no-sandbox` などの環境向け起動フラグもこのテストに限定しています。本番Edge起動には付けていません。

自動テストの成功は実サイトでの入力・保存確認を意味しません。実画面の読取診断には `check-screen.bat` を使い、DOMや入力確定・保存経路の確認は [docs/selectors.md](docs/selectors.md) に従います。過去の実画面検証の記録は [docs/verification.md](docs/verification.md) を参照してください。
