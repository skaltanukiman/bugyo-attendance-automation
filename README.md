# 奉行クラウド 勤務実績入力自動化

Windows上で作業実績Excelを読み取り、利用者が開いた奉行クラウドの勤務実績申請画面へ転記し、検証後に**下書き保存まで**行うローカルツールです。ログイン、MFA、入力画面までの移動、最終「申請」は利用者が手動で行います。保存後は下書き一覧から対象月を開き直して内容を確認します。

添付Excelの解析と模擬画面の操作テストに加え、利用者の通しテストで全対象日の入力・入力値検証と、下書き保存後の画面遷移まで確認されています。保存済み下書きの全対象日の照合とExcelコピーの退避も完了しました。実画面での確認完了後、通常実行の利用に合わせて `config/selectors.json` を `verified: true` に切り替えました。`run.bat` から利用できます。年月表示のない入力画面では全日付行の年月日属性を照合します。通常の `run.bat` は未確認設定を拒否します。通常実行への切替方法と確認範囲は [セレクタ設定手順](docs/selectors.md) と [検証結果](docs/verification.md) を参照してください。

## 初回セットアップ

1. WindowsにNode.js 22以降（npm付属）とMicrosoft Edgeをインストールします。
2. このフォルダで `npm install` を実行します。ブラウザの追加ダウンロードは不要です。
3. `npm run check` と `npm test` を実行します。テストは既存のEdgeを使い、専用の一時プロファイルでローカル画面を検証します。
4. 実DOMに合わせて `config/selectors.json` を設定します。

依存バージョンを固定したpnpm用ロックファイルもあります。pnpm利用時は `pnpm install --frozen-lockfile` を使えます。Excel読み取りはSheetJS公式配布の0.20.3を使用します（旧npm版ではありません）。

## 保存後の確認だけを再開する

入力・検証が完了し、下書き保存後の「申請期間」画面で停止した場合は `verify-draft.bat` を使います。

1. `input/` のExcelをそのまま使い、`verify-draft.bat` をダブルクリックします。保存時と同じ出社日・有休日を指定して開始します。
2. 起動済みの専用Edgeがあれば接続し、なければ起動します。必要ならログインし、下書き件数・「申請期間」・OKが表示される画面を開いて、コンソールでEnterを押します。「下書き:N件」は自動で開きます。
3. 対象月の下書きを一意に特定して開き、全対象日の保存内容をExcelと照合します。一致した場合だけExcelを `filesback/` に退避します。

この実行では入力・再保存・申請・削除をしません。別月・重複・値の不一致ではExcelを保持します。未確認設定でも再確認できますが、`verified` を変更せず、設定が確認済みでも入力・保存は拒否します。

画面の読み込みと一時的なタイトル重複が解消するまで、各遷移で最大60秒待機します。タイトルだけでなく保存ボタン・日付行・読取項目が揃ってから照合します。完了表示が出るまでは専用Edgeを開いたままにしてください。

## 実画面の読取確認（任意）

1. `check-screen.bat` をダブルクリックします。対象Excelの配置は不要です。
2. 対象年月を西暦6桁で入力し、手動で入力確認した日を指定します。
3. 起動した専用Edgeで手動ログインし、対象月の「勤務実績申請」入力画面を開きます。編集中の時刻・休憩欄を確定してからコンソールに戻りEnterを押します。
4. 「確認成功」と確認日の6項目が表示されたら、値が画面と一致するか確認します。エラーなら表示された段階とメッセージを確認してください。

このモードは全日付と各日の既存値を読み取るだけです。クリック・自動入力・保存・申請・Excel解析や退避は行いません。`verified` は変更せず、通常実行の有効・無効は設定値に従います。勤務値はコンソールだけに表示し、ログファイルを作成しません。結果を共有する場合は「成功と値の一致」、またはエラーメッセージだけで足ります。専用Edgeは終了後も開いたままです。前回の専用Edgeが残っている場合は閉じてから起動します。

## 毎月の利用

1. 対象Excelを `input/` に配置します。ファイル名は `YYYYMM_名称.xls` または `.xlsx`。例: `202610_勤務実績.xlsx`。名称は自由ですが、Excelの内部レイアウトは対応テンプレートである必要があります。
2. `run.bat` をダブルクリックします。複数ファイルがある場合は番号で選択します。
3. 出社日を `3,18,25` または `3、18、25` のように入力します。ない場合はEnter。
4. 有休日を任意入力します。後で奉行上で入力する場合はEnterで続行できます。Excelの空欄や「休暇」という記述から休暇種別は推測しません。
5. 日数・時間・出社日・有休日を確認して `Y`。`n` ならブラウザやExcelを変更せず終了します。
6. 起動した専用Edgeで手動ログインし、「勤務実績申請」画面で対象年月を表示します。コンソールへ戻ってEnterを押します。
7. 年が画面から取得できない場合は追加確認があります。月違いや不明瞭な年月表示では入力しません。
8. 入力・検証・下書き保存の成功後もEdgeは開いたままです。内容を確認し、必要な有休などを追記して、**自分で「申請」してください**。

自動処理中は対象画面やExcelを編集しないでください。非勤務日で有休指定されていない行は変更しません。休日候補の自動判定は行いません。

## 設定

`config/settings.json` の設定だけで勤務体系・事由を変更できます。

| 設定 | 初期値・意味 |
| --- | --- |
| `attendance.workPatternCode` | `"205"`。勤務・指定有休日に設定 |
| `attendance.remoteReasonCode` | `"007"`。通常勤務の既定事由 |
| `attendance.officeReasonCode` | `null`。出社は事由を空欄。`"006"`等への変更も可能 |
| `attendance.paidLeaveReasonCode` | `"040"`。明示された有休日のみ |
| `files.inputDirectory` | `input` |
| `files.backupDirectory` | `filesback` |
| `files.supportedExtensions` | `.xls`, `.xlsx` |
| `files.backupTimestampFormat` | `yyyyMMddHHmmss`。日時は日本時間 |
| `browser.remoteDebuggingPort` | `9222`。localhostへのCDP接続用 |
| `browser.userDataDirectory` | `.runtime/edge-profile`。通常のEdgeと独立した専用プロファイル |
| `browser.executablePath` | `null`。標準インストール先から自動検出。必要なら絶対パスを指定 |

日時書式は `yyyy`, `MM`, `dd`, `HH`, `mm`, `ss` と区切りの `-`, `_` に対応します。相対パスはこのプロジェクトを基準とします。

## Excel対応範囲

添付2ファイルを実測したセル配置に対応しています。詳細は [調査結果](docs/investigation.md)。Readerと解析ロジックは分離し、`.xls`・`.xlsx`とも同じテンプレートを読めます。テンプレートが変われば解析アダプターの追加が必要です。ヘッダー・明細全日付・時分・合計を検証し、不明なレイアウトで推測転記しません。

数式はExcelで保存された計算結果を読み、Node.jsでExcel数式を再計算しません。日別の出退勤差分、休憩、実働と合計値を突き合わせます。Excelで再計算してから保存してください。日跨ぎは終了時を24時以上（最大47:59）で記録する形式のみ対応し、翌日扱いを推測しません。

## 再実行・エラー時

- 既存値が全項目一致すれば `ALREADY OK` で入力を省略します。
- 全対象日を先に調べ、時刻や事由が競合すれば一切入力せず停止します。勤務体系変更と、明示した出社日に残る在宅事由の変更は許可します。
- Excel上の勤務実績日を有休に指定した場合はエラーです。元データを確認してください。
- 途中失敗では入力済み行が画面に残ることがあります。自動ロールバックや申請は行いません。
- 検証成功後、下書き保存を1回だけ行います。申請期間画面へ戻った後、下書き一覧で対象月全体の「勤務実績申請」を一意に特定し、開き直して対象年月と全処理対象日の保存内容を照合します。一致した場合だけ、使用ファイルを `filesback/YYYYMMDDHHMMSS/元ファイル名` へ移動します。既存下書きの更新で件数が変わらなくても対応できます。対象不明・複数候補・内容不一致では停止し、Excelを保持します。自動で保存を再試行しません。
- 保存未確認ならExcelは `input/` に残ります。保存ボタン押下後の通信切断などでは保存済みの可能性もあるため、画面を確認してください。
- 下書き成功後のバックアップだけが失敗した場合は警告（終了コード2）。下書きはそのままで、Excelを手動退避します。同秒ディレクトリが既にある場合も上書きせず停止します。
- 通常成功は終了コード0、その他エラーは1です。`run.bat` は結果を表示したまま待機します。
- `logs/` に処理段階・日別結果・差異を記録します。生のブラウザエラー、HTML、Cookie、認証情報は記録しません。ログには勤務日時が含まれるため適切に管理してください。
- デバッグポート使用中なら前回の専用Edgeを手動で閉じてください。プロファイルを使ったEdgeを残したまま再起動しません。
- 強制終了後に `.runtime/run.lock` が残った場合、別の実行がないことを確認して、このファイルだけを削除してください。
- `.runtime/edge-profile` は認証状態を含む場合があるため、共有・コミットしないでください。パスワードを設定ファイルへ書く必要はありません。

## 開発・検証

```text
npm run check
npm test
```

自動テストは架空の明細データと模擬画面を使用します。添付原本の読取検証は完了済みで、原本専用の検証スクリプトは削除しています。原本と実際の勤怠日付・集計値はリポジトリに含めません。

`tests/fixtures/attendance.html` は実DOMの再現ではなく、日付による操作・競合・保存検証・申請禁止を確認するための模擬画面です。ブラウザテストはMicrosoft Edge標準インストールを必要とします。CDPテストのみ `EDGE_PATH` で実行ファイルの変更が可能です。

この作業環境では独立起動するヘッドレスEdgeのテストに限り、サンドボックス内で動作させるため `--no-sandbox` を付けています。実運用のEdge起動処理にはこのフラグを付けていません。

構成は `src/excel`（読取と解析）、`src/domain`（型と設定）、`src/services`（業務検証・入力手順・退避）、`src/browser`（Page Object・セレクタ・Edge）、`src/cli`（対話と表示）に分離しています。最終申請の操作メソッドはありません。
