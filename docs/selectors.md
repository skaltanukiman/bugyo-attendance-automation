# 実画面へのセレクタ設定

`src/browser/attendancePage.ts` にDOMの構造やCSSクラスを埋め込まず、`config/selectors.json` に分離しています。未設定の要素があるか `verified: false` の間は自動操作に進みません。以下は将来の実画面確認担当者向けの手順です。

## 確認する情報

1. 勤務実績申請の見出し、対象年月専用の表示要素、対象iframeの有無。
2. 日付行の親要素、行内の日付セル（`9/ 1 (火)`など）。年月表示は `令和8年9月`、`2026年9月`、`9月`を受理します。月だけの場合は利用者へ年を追加確認します。
3. 各行の勤務体系・事由・出退勤・休憩・実働を読み取る要素。`readMode: text` はセル本文、`value` はinput/select値を読みます。コードは数字のまま、または`205 エンジニア`のような表示を受理します。
4. 入力欄と操作方式。ネイティブinputは `fill`、ネイティブselectは `select`。値は勤務体系・事由のコード、時刻は`09:00`、休憩は小数時間`1.00`です。selectのoption値がコードと一致することを確認してください。
5. 編集ダイアログがある場合は行内の `editButton`、画面内の `editor`、編集画面内の `applyButton` をすべて設定します。直接編集ならすべて `null`。行確定ボタンはsubmitではなく、最終申請に無関係なものであることを確認してください。
6. 下書き保存後に**新たに表示される**成功メッセージの要素を `saveSuccess`、正確な本文を `saveSuccessText` に設定します。常に表示される件数・前回成功表示をそのまま使わないでください。ボタン押下だけでは成功になりません。

保存ボタンは変更可能な自由セレクタではなく、role=button、正確な名前「下書き保存」で固定します。最終「申請」のセレクタや操作メソッドはありません。クリック共通ガードで「申請」を含む名前・タイトル・本文を拒否します。

## 設定のスコープ

| キー | 検索範囲 |
| --- | --- |
| `frame` | ページ。iframeセレクタ1つ。なければnull |
| `title`, `period`, `rows`, `editor`, `saveSuccess` | ページまたは対象iframe |
| `dateCell`, `fields.*.read`, `editButton` | 該当する日付行 |
| `fields.*.input`, `applyButton` | 編集ダイアログ、または直接編集時の日付行 |
| custom方式の `option` | ページまたは対象iframe |
| custom方式の `clear` | 編集ダイアログまたは日付行 |

`rows` は全日付行にマッチさせ、`dateCell` を正規表現で照合して日付行を特定します。行番号やクリック座標は使いません。日付行・入力欄の重複や非表示は停止条件です。仮想スクロールで未表示行がDOMにない場合も推測で進めず停止します。必要ならDOM確認後にスクロール用アダプターを追加してください。

customドロップダウンでは `control: "custom"`、コード置換用 `option: "[data-code='{code}']"` のような実際に確認したセレクタ、空欄へ戻す `clear` を設定します。これは形式例であり、奉行にこの属性があるという意味ではありません。

`tests/fixtures/selectors.json` に完成した**模擬画面専用**設定があります。キーの参考としてだけ使用し、実サイトへコピーしないでください。複数iframe階層、時分別入力、候補検索で確定する複雑なUI、保存確認ダイアログなどは実DOM確認後にPage Objectのアダプターを拡張する必要があります。未対応方式をセレクタだけで対応可能とは扱いません。

実画面の構造・値の単位・保存完了本文を確認してから `verified: true` にします。ログインID、Cookie、HTML全体などを設定やログへ保存する必要はありません。

## 検証の境界

保存前の勤務日数・実働・休憩は、全対象行を読み戻してExcelと比較します。非対象行は変更しないため、月全体の表示合計ではなく今回処理対象の合計です。指定した有休日は各行の事由・勤務体系と、通常勤務時間が空欄またはゼロであることを検証します。未指定の有休件数は比較しません。

模擬テストでは申請ボタンにカウンタを設け、正常系・異常系ともゼロを検証しています。実画面への接続確認、実データでの入力、実サイトの下書き保存は今回実施していません。
