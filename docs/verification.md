# 検証結果

実施日: 2026年10月4日（日本時間）

仕様書、添付Excel、提供HTML・スクリーンショットを基に実装しました。初期範囲は設定分離と模擬画面テストでしたが、その後、利用者の指示により実画面の通しテストへ進めています。原本・実際の勤怠日付や集計値・氏名・組織固有URL・暗号化IDは資料やテストへ保存していません。

| 検証 | 結果 |
| --- | --- |
| TypeScript型検査 | 成功 |
| 自動テスト | 計58件。架空明細・ローカル模擬画面を使用 |
| 添付 .xls 2件の読取 | 日付・勤務日数・実働・休憩の照合成功。利用者による再実行も成功 |
| 実画面への読取接続 | 非表示の同名タイトルを除外し、対象画面・年月・全日付・6項目の読取に成功 |
| 利用者の実画面通しテスト | 全対象日の入力・入力値検証と、保存後の申請期間画面への遷移まで確認。下書きを開き直す確認で停止 |
| 保存内容の実画面照合・Excel退避 | 未完了。件数や遷移だけでは成功とせず、Excelをinputに保持 |

型検査・テストは `npm run check` / `npm test` 相当の、インストール済みTypeScript・tsxをNodeで直接実行しています。この環境にnpmコマンドがなかったため、依存取得にはpnpmを使用しました。

## 入力と検証

日付行の左右の表・重複ID、年月日属性、分割時刻、小数時間、在宅・出社・明示有休、全対象日の事前競合確認、再実行、編集ダイアログ方式を模擬画面で検証しています。年月・日付・既存値の不一致、複数事由、未確定の手入力、確定失敗では停止します。

実画面ではコード属性が変更前の値を保持し、自動操作が開いた勤務体系欄を未確定の手入力と誤判定していました。現在は表示コードを読み、自動操作が開く直前の表示コードと現在のinputValueを照合します。HTMLのvalue属性が空でも現在値を確認し、外部で開かれた編集欄や編集値が変わった場合は停止します。修正後、利用者の通しテストで全対象日の入力と検証が完了しています。

読取専用の `check-screen.bat` は全日付・6項目を読み、確認日の値をコンソールだけに表示します。クリック・入力・保存・Excel退避・ログ作成・設定変更は行いません。

## 保存後の再表示

新規保存と件数が変わらない更新保存、古い保存値、対象期間の重複・別月・承認待ち・部分期間、遷移失敗、和暦・西暦の月初から月末の照合を検証しています。対象行のリンクで詳細を表示し、「申請書入力」で戻る2段階を提供HTMLに基づくセレクタで検証します。詳細表示失敗・ボタン重複・再表示後の年月違いでは成功扱いにしません。正常・異常とも保存クリックは1回、申請・削除は0回です。

最新の通しテストでは、保存後の申請期間画面に遷移した後、再表示操作で「操作対象がない、複数ある、または非表示」のエラーになりました。接続時の読み取りでは、表示中の下書き一覧入口が1件あり、type未指定のbuttonでした。その後、専用Edgeへの接続が切れたため、この修正の実画面での再実行は未確認です。

保存直後の入口を待つ処理と、非表示テンプレートを除外する処理を追加しました。入口ボタンは下書き件数の表示名を厳密に照合し、typeがbutton、またはtype未指定かつフォーム所有なしの場合だけ操作します。フォーム送信・明示submit・誤った申請/削除要素は拒否します。待機失敗時は停止箇所を識別するメッセージを返します。

入口が目印より遅れて表示される模擬画面、非表示の同名テンプレート、フォーム所有の有無と送信禁止を追加検証しました。保存確認を再開する `verify-draft.bat` も追加し、保存済み内容の一致時だけ検証済み・保存確認済みにすることをテストしています。不一致では両方falseのままです。再確認専用モードでは、設定が確認済みであっても入力・保存を拒否し、保存・申請・削除カウンタはすべて0です。

本番設定は `verified: false` を維持しています。通常実行は未確認設定を拒否し、明示した通しテストのみ入力と保存を許可します。再確認専用モードは下書きの再表示・照合と、成功時のExcel退避だけを行います。添付原本の書き換えや退避は行いません。原本専用の検証スクリプトは照合完了後に削除済みです。
