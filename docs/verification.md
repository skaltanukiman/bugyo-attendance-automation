# 検証結果

実施日: 2026年10月4日（日本時間）

対象は仕様書、添付Excel、追加提供されたHTMLとスクリーンショットです。初期範囲は「設定分離と模擬画面テストまで」でした。その後、利用者が実画面の通しテストを希望したため、専用の起動方法を追加しています。実画面での通しテストの結果はまだ未確認です。原本の対象年月・勤怠値は掲載しません。

| 検証 | 結果 |
| --- | --- |
| TypeScript型検査 | 成功 |
| 自動テスト | 初期26件に分割セル・年月日属性関連8件、保存件数・遷移関連4件、下書き再表示関連8件、読取専用関連3件、通しテスト起動関連2件、タイトル・タブ識別関連2件を追加。計53件 |
| 実画面の読取接続 | 非表示の同名タイトルを除外して入力画面を識別し、対象年月・全日付・各日の6項目の読取に成功。画面への入力・保存は未実施 |
| 読取専用モード | 全日付・6項目の読取、未確認設定での入力と保存の拒否、日付欠落・重複・別年・項目欠落での停止を模擬画面で確認 |
| 通しテスト起動 | 明示したtrialモードで未確認設定から入力・保存・再読取。通常モードと不正設定は拒否し、trialでも年月違い・競合で入力前に停止 |
| Windows起動バッチ | LF改行でのcmd.exe解析エラーを再現し、UTF-8・CRLFへ修正。実処理を動かさない代替CLIで3種類の起動引数、依存不足とNode未検出のメッセージ・終了コードを確認 |

| ファイル退避 | 保存・検証成功時のみ移動。不成功、同時刻衝突、元ファイル変更では元を保持 |

実行コマンドは `npm run check` / `npm test` 相当の、インストール済みTypeScript・tsxをNodeで直接実行したものです。この環境にnpmコマンドがなかったため、依存取得はpnpmを使用しました。

本番の `config/selectors.json` は提供HTMLで確認できた箇所のみ反映し、`verified: false` を残しています。専用Edgeへの読取接続と入力画面の識別・全日付の読取は実施しました。実勤務データの転記、本番下書き保存、添付Excel原本の書き換えや退避は実施していません。

原本専用の検証スクリプトと実行設定は、原本照合完了後に削除しました。残している自動テストは架空の明細・模擬画面を使用します。匿名化時に初期26件の成功を確認し、画面識別の修正後も型検査と全53件を再実行しています。

利用者から、実画面で日付行の絞り込み後の件数が対象月の日数に一致したこと、出退勤・休憩の手動入力後に別の入力欄へ移動しても表示値が残ることが報告されています。利用者の通しテストでは、非表示の同名タイトルまで数えていたため入力前の画面識別で停止しました。修正後、実画面で表示中のタイトル・下書き保存ボタンを一意に特定し、全日付の既存値を読み取れました。診断出力は要素件数のみで、実際の勤怠値・氏名・URL・HTMLは保存していません。`check-screen.bat` は既存値をコンソールに表示するだけで、クリック・保存・Excel退避・ログファイル作成・verified変更を行いません。通常実行は引き続き未確認設定を拒否します。

下書き再表示のテストは、新規保存と件数が変わらない更新保存、保存値が古い場合、対象期間の重複・別月・承認待ち・部分期間、保存後の遷移失敗、和暦・西暦の全月期間照合を検証します。一覧の左右に分かれた行からリンクで詳細を表示し、「申請書入力」で戻る2段階を模擬画面で検証します。詳細表示失敗・入力ボタン重複・再表示後の年月違い、誤ったセレクタでの申請・削除・submitボタン・移動先付きリンクの拒否も確認します。保存を1回だけ行い、申請・削除を行わないことをカウンタで検証します。本番の一覧と「申請書入力」ボタンのセレクタは提供HTMLを基に設定し、同じ設定で模擬画面を検証しています。実ページでの一意性と自動操作は未確認です。

保存件数のテストは、新規下書きの1件増加と遷移、件数不変・想定外増加・遷移未確認時の停止、保存前に件数が取得できない場合の非操作、ページ全体の遷移後の再読取を検証します。テストの遷移先はPlaywright内で応答する架空URLで、実サイトへの保存は行いません。

追加テストは、左右に分かれた行と重複ID、コード属性と現在の入力値、小数時間の分割入力、行の日付属性不一致、複数事由・未確定入力の保護、確定失敗時の停止、翌日の時間タイプ変換を対象にしています。実サイトのJavaScriptの確定動作は再現できていないため、模擬テスト成功だけで本番設定を有効化しません。
